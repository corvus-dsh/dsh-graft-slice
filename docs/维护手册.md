# graft-slice 维护手册

> 这份手册回答四个问题：**改的时候守什么**、**怎么知道没改坏**、**跑不动时怎么办**、**证据放哪**。
> 它不重复 README（那是给使用者看的）与 ARCHITECTURE（那是给读者的决策记录），
> 只写「维护者每天要用到、而别处不写就会忘」的那些规则。

---

## 一、六条搬移纪律（每次搬代码都适用）

| # | 纪律 | 为什么 |
|---|---|---|
| 1 | **新模块不加新注释文字**。解释写进提交信息，源码里最多留一行指向它 | 注释是散文，散文会腐坏；搬移的正当性属于提交历史，不属于源码 |
| 2 | **注释里不写可被解析的 import 字面量** | 扫描器（`who-references`、`verify-import-edges`）读的是文本，注释里的 `import` 会被算成真实依赖 |
| 3 | **必须看到 `verify-pure-move` 报 `IDENTICAL`**，而且是对**父提交**跑 | 对 `HEAD` 跑等于拿工作树和自己比，永远相同 —— 那是空洞运行（工具会拒绝，exit 2） |
| 4 | **值导出必须重导出**：`import` + 裸 `export { x }` | 打包器要求；用 `export … from` 会得到「unresolved relative import」 |
| 5 | **搬完重跑 `families.mjs`，把新分量表原样写进提交信息** | 分量表只在搬的那一刻有意义，事后无法复现当时的地图 |
| 6 | **跑完全部门禁，并在提交信息里列出各自的结果** | 「我跑过了」不是证据，逐项的退出码与计数才是 |

**尺寸一律三口径**（`scripts/measure-move.mjs` 输出）：
① 声明跨度和；② 切除区间；③ `index.ts` 实测净变化。三者互不相等是正常的，**只报其中一个就是错**。

## 二、门禁清单（GATE：必须是 CI 步骤，红就是红）

| 门禁 | 守什么 | 典型红因 |
|---|---|---|
| `check-docs.mjs` | README/ARCHITECTURE 里声明的计数与代码一致 | 改了测试数没同步 README |
| `check-readme-counts.mjs` | 文档里的**现值数字**必须有口径与时点限定 | 写了「11,704 行」但实际不是 |
| `check-readme-tally.mjs` | `passed + skipped == total`，且与实测一致 | 新增测试后没同步 |
| `verify-bundle.mjs` | 打包契约 + 导出面基线（当前 182） | 增删导出没更新基线 |
| `check-cycles.mjs` | 依赖图无环，且**每条相对 import 都能解析** | 少一个模块 / 拼错路径 |
| `check-artifact-fresh.mjs` | 提交的 `index.js` 就是当前源码构建出来的 | 改了 `src/` 没重建 |
| `v140`（`audit-line-numbers.mjs` 的消费方） | 硬编码行号清单 | 行号漂移 |

**门槛与仪器不是门禁**（见下节），它们**打印结论，不红 CI**。

## 三、仪器清单（INSTRUMENT：回答一个问题，跑不跑由人定）

| 仪器 | 回答什么 | 什么时候必须跑 |
|---|---|---|
| `closure.mjs` | 一个声明（或一段行区间）的依赖闭包有多大 | 决定能不能搬之前 |
| `families.mjs` | 闭包里还有哪些彼此纠缠的簇 | 每次搬完 |
| `move-gate.mjs` | 一个簇的四档（A/B/C/D）预判 | 搬之前 |
| `who-references.mjs` | 谁引用了这个符号（含歧义名剔除） | 判断有没有族外调用者 |
| `calibrate-who-references.mjs` | `who-references` 自己还可不可信 | 每次 `who-references` 出错之后 |
| `verify-pure-move.mjs` | 这次改动是不是纯位移 | 每次搬移，对**父提交** |
| `verify-import-edges.mjs` | 有没有新增 import 依赖（`verify-pure-move` 看不见它们） | 每次搬移 |
| `verify-bundle-purity.mjs` | 产物里的**代码行多重集**有没有变 | 每次搬移 |
| `measure-move.mjs` | 三个尺寸口径 | 每次搬移 |
| `measure-efficiency.mjs` | 相对性能（主统计量 + 分辨率） | 每次搬移、每次性能声明 |
| `type-check.mjs` | 三分类诊断（CODE HEALTH / ENVIRONMENT / ARTIFACT） | 改类型相关代码后 |
| `type-budget.mjs` | 每个文件的诊断计数与**身份多重集**不许增长 | 同上 |
| `inventory-source-guards.mjs` | 源码护栏清单 | 新增护栏后 |
| `audit-line-numbers.mjs` | 硬编码行号审计表 | 行号相关改动后 |

各仪器的**已知盲区**登记在 `docs/backlog/graft-slice-phase-a-issues.md` 的 B 系列。
用它们的输出下判断之前，先看那一节。

## 四、跑不动时怎么办（RESOURCE 规则）

**核心一句：缺少资源是「跳过」，不是「通过」。**

| 情况 | 正确反应 |
|---|---|
| 没有 TypeScript 编译器（本包零依赖，CI 上必然没有） | `closure` / `type-check` / `type-budget` / `move-gate` **exit 2**；测试用 `t.skip('RESOURCE: …')` |
| 没有 `npm`（例如子进程 PATH 里没有） | `v146` 跳过并写明原因 |
| 缺真实会话日志 | 相关测试跳过（`corpus absent … — provenance unverified in this checkout (not a pass)`） |
| 机器噪声太大（`measure-efficiency` 的 worst control > 10%） | 仪器自认 `INSTRUMENT UNFIT` 并 exit 2；**不许调小轮数去凑结论** |

三条禁令：
1. **不许把 skip 说成绿。** 跳过必须在输出里被看见。
2. **不许用"本机能跑通"当判据** —— 那正是 `D:/…` 硬编码在 CI 上翻车的形状。
3. **不许为了让某个结论成立而降标准**（轮数、样本量、阈值）。

## 五、新模块加入流程

1. **判断闭包是否闭合**：`node scripts/closure.mjs <声明名>`，`OUTSIDE` 必须为 0（不为 0 时先看是不是 `closure` 的遮蔽盲区，见 B-2）。
2. **建文件**：只搬声明本身，**不写新注释**；`index.ts` 侧加 `import` + 裸 `export { … }`。
3. **重建并核对**：
   - `node scripts/build.mjs`
   - `node scripts/verify-pure-move.mjs --against <父提交> → IDENTICAL`
   - `node scripts/verify-bundle-purity.mjs --before <父提交> → BUNDLE PURE`
   - `node scripts/measure-move.mjs --from <父提交> --to working --decl <名字…> → 三个数`
4. **进登记表**：在 `ARCHITECTURE.md` 的 `### TD-1a` 加一行（模块 / 职责一句话 / 导出 / 依赖）。
   `test/v145` 会**双向**核对你：漏登记要红，登记了不存在的文件也要红。
5. **跑全部门禁 + 全套测试**，再跑一次 `families.mjs`，把分量表与三口径写进提交信息。
6. **尺寸上限**：单模块 ≤ 800 行，由 `test/v130` 执行；两张豁免表内的模块不许再增长。

## 六、覆盖率判据（怎么数才算数）

`src/core` 的模块数**只有一条权威来源**：`ARCHITECTURE.md` 的 `### TD-1a` 登记表。
`test/v145` 双向核对它 —— 表里少一行、多一行、指向不存在的文件、依赖列指空，都会红。

**别再按散文数。** 从 ARCHITECTURE 正文用正则捞 `core/<name>.ts` 得到的数，会因为
「某一行顺带提了一句」而变。实测：S-1 脱敏把 `…/store-layer.ts` 改成
`<repo>/src/core/store-layer.ts`，`core/` 前缀一加上去，「提到」数就从 13 跳到 14。
**散文里的提及数不是覆盖率。**

### 分母怎么取（三种都合法，但必须写明用哪一种）

| 算法 | 判据 | graft-slice 当时的数 |
|---|---|---|
| **A（推荐，也是 `v145` 用的）** | `readdirSync(dir).filter(f => f.endsWith('.ts'))` | **28** |
| B | 名字里含 `.ts`（会把 `x.ts.bak-cut` 也算进来） | 29 |
| C | 只数 `.bak-cut` | 1 |

选 A 的理由：`ignition.ts.bak-cut` 是**证据文件不是模块**，它不以 `.ts` 结尾，天然被排除。
`check-cycles` / `closure` 同样排除它，而 `type-check` 会把它打印成
`excluded (evidence, not source)` —— **打印出来，而不是静默跳过**。

### 登记表里的名字可以写短，但比较时要归一

`TD-1a` 的行首写 `` `core/watermark.ts` ``（仓库内习惯的相对写法），磁盘上是
`src/core/watermark.ts`。两种都合法：

- **行首**：写 `core/x.ts`（短，与依赖列一致）；
- **比较时**：读写双方都归一 —— 缺 `src/` 前缀就补上，再比。

`v145` 就是这么做的。哪天把行首改成全路径，测试同样能过 —— 判据是「**归一后相等**」，
不是「字面相等」。无论选哪种，**必须写在表头或测试注释里**，否则下一个人会当成笔误。

**一条纪律**：任何「模块数 / 覆盖数」的结论，都要指明**算法 + 数 + 在哪张表**。
只给一个数字，等于没给。

## 七、证据落盘规则

**原则：结论不算证据，原始读数才算。** 每条结论都要能追到一份可复算的记录。

| 证据 | 落在哪 | 关键要求 |
|---|---|---|
| 搬移的三口径 | 提交信息 | 注明来源脚本；三个数都要有 |
| 分量表 | 提交信息 + `ARCHITECTURE.md` 的族快照表 | 标「当时」，不与新口径直接比较 |
| 性能读数 | **`_scratch/efficiency-runs.jsonl`**（`measure-efficiency --out`，默认路径） | 每行含每轮 `beforeBest/afterBest/delta/control` + `primary` + `quality` + 两个 bundle 的 sha256；**足以独立复算** |
| 旧版基线 | `_scratch/baseline.json`（`build-old-baseline.mjs`） | 记 ref、sha、字节、sha256 |
| 差分结果 | 提交信息 + 清单第六/七节 | 表头写两个产物的 sha256；旧表要标「已过期」 |
| 类型状态 | `type-budget.mjs` 的两张基线表 | 诊断**身份**（文件+代码+消息），不是行号 |

`_scratch/` 已在 `.gitignore` 里：**本地实验与测量记录不提交**，提交的是由它们得出的结论与命令。

## 八、缺陷登记在哪

- **本仓库的已知问题** → `docs/backlog/graft-slice-phase-a-issues.md`。
  - A 系列：类型层的三笔账（真缺陷 / 环境 / 编译器产物）。
  - B 系列：**仪器盲区**（`who-references`、`closure --block`、`families`、`verify-pure-move`、`measure-efficiency`）。
  - 「已知脱敏项」也在这份清单里。
- **一条缺陷升格为门禁的条件**：它已经**实际发生过一次**，且能被机器判。只是「可能发生」的写进清单，不写门禁。
- **修复顺序**：先修仪器，再修被测对象。仪器错了，后面每一次判断都建在错的地基上。

## 九、几个反复踩到的坑（先看这里，再怀疑代码）

1. **用位置当身份** —— 行号、硬编码计数、子串匹配、列 0 作用域判断。会变的东西必须测量。
2. **同名多声明** —— 文本匹配无法区分作用域；`name` 这类名字在整棵树里有 17 个声明点（见清单 B-1）。
3. **会改真实树的测试** —— 并行运行器下会毒害别的测试；探针一律写进 `mkdtemp` 副本，用 `GRAFT_*_SRC` 指过去。
4. **单次性能结论** —— 单轮运行报过 +23.83% 的假回归；性能结论必须多轮独立 + 符号一致（见清单 B-6）。
5. **「跑过了」当成「通过了」** —— 空洞运行（工作树 vs HEAD）、skip 当成绿、分母为 0 的绿灯，都是同一类错误。

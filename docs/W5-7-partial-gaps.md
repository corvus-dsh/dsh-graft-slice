# W5-7 部分通过：两处缺口，以及它们为什么停在这里

> 这份文件存在的原因：W5-7 的判据是「三条做完、一条判、一条未确认」，如果只在验收报告里写一句
> 「部分通过」，下一个读验收的人会以为 7 条全部通过。**缺口必须能按名字查。**

## ① `.bak-cut` 不删、不移 —— 决定已记录

- 文件：`dsh-graft-slice/src/core/ignition.ts.bak-cut`（31 KB，v7.6 切割前的基线备份，
  2026-11-05 22:35）。
- 派工单写的是「删除/移出 `.bak-cut`」。**没有执行**，因为它被**五处**钉着：

| 位置 | 它钉的是什么 |
|---|---|
| `test/v125-historical-evidence-guard.test.mjs` | 这个文件存在，且仍被两份报告引用 —— 断言它是**证据**而不是代码 |
| `test/v126-source-scan-coverage.test.mjs` | 它是扫描谓词「含 `.ts` 但不以 `.ts` 结尾」的**边界样本**（`mustMatch` 名单里写着它） |
| `test/v130-module-size-cap.test.mjs` | cap 扫描集的边界样本（「contains .ts but does not end in it」） |
| `test/v142-type-check-signal.test.mjs` | 断言它**不进**类型诊断（`excluded (evidence, not source)` 那行） |
| `scripts/move-gate.mjs` / `scripts/type-check.mjs` | 两处 `NOT_SHIPPED` / `NOT_SOURCE` 名单各写着它 |

删掉它不是「打扫干净」，是**把五条守卫的锚点删掉**——那五条会连同它们保护的行为一起消失，
而测试全绿。这正是本批反复记录的形状：**让检查通过的改动，未必是让事实变好的改动。**

**若将来确实要删**，正确的顺序是：先改那五处（换成另一个边界样本并说明为什么换），
再删文件，再确认 `v125` 的存在性断言被改成「此证据已归档到某处」而不是被删掉。

## ② 日期口径 11-18 / 11-19 —— **未确认**

派工单要求「日期统一为实际收口日」。**没有批量改**，原因不是懒得查，是**没找到那一处**：
这两个日期出现在**不同条目**上，各自是那一条的登记日／关闭日（例如 TD-M17 登记 11-18、
B3 收口 11-19），**没有找到「同一件事被写成两个日期」的实例**。

在没有具体目标的情况下批量替换日期，会把正确的登记日一起改错——那是拿一个可验证的事实换
一个更好看的表面。

**判据（可执行）**：若后续发现某一处「同一事件两个日期」，以**提交时间**为准（`git log`
的 author date），并在该处写明「以提交 X 的时间为准」。

## 1. profile 目录（**不用 desktop**）

```powershell
# 新建一个一次性 profile（名字自取）
$env:DSH_PROFILE_DIR = 'C:\Users\89283\.dsh\profiles\graft-smoke'
New-Item -ItemType Directory -Force -Path $env:DSH_PROFILE_DIR | Out-Null
$env:DSH_PROFILE = 'graft-smoke'      # 与目录名保持一致
```

- **不许**把 `DSH_PROFILE_DIR` 指向 `desktop`；理由见交接说明第二节。
- 记下当前 `desktop` 的插件来源与版本（**替换前留底**）：
  `dsh plugin list` 的输出整段存一份。

## 2. 安装命令

```powershell
dsh plugin list                                            # 装之前：看清基线
dsh plugin add "D:\持久层能力架构\dsh-graft-slice\corvus-dsh-dsh-graft-slice-0.9.2-beta.1.tgz"
dsh plugin list                                            # 装之后：版本 + 来源都变了
```

> 已知阻塞：`dsh` 可能不在 PATH（本机实测 `where dsh` → exit 1）。
> 若如此，**先解决 CLI 可用性**，不要手改 profile 目录来模拟安装。

## 3. 三条验证

| # | 做什么 | 通过判据 |
|---|---|---|
| 1 | `plugin_manager` 的 `list_bundles` | 版本 = `0.9.2-beta.1`；来源是那个 tarball，**不再是 `link:`** |
| 2 | `graft_debug_status` | 正常返回水位/锁/待裁定状态（证明插件加载起来、Service 注册成功） |
| 3 | 一次**真实**切片（`graft_slice_and_inject`） | 返回 `ok`；目标会话可冷启动；看板里有锚点行，且锚点文案是三种之一（`第 N 代会话` / `一个原始会话` / `一个代次未记录的会话`） |

补充（可选，成本低）：`graft_read_result` 回读一个 seq，确认指针可解析。

## 4. 回滚

```powershell
dsh plugin remove dsh-graft-slice
# 还原到第 1 步记下的那个来源：
#   · 若是 link：git -C D:\持久层能力架构\dsh-graft-slice checkout <替换前记下的 HEAD>，再 dsh plugin add <该目录>
#   · 若是 registry 版本：dsh plugin add @corvus-dsh/dsh-graft-slice@0.9.0-beta.2
dsh plugin list     # 确认回到旧版
```

回滚后重跑第 3 节的三条验证。

**独立 profile 的回滚更简单**：直接删掉 `$env:DSH_PROFILE_DIR` 那个目录即可，`desktop` 全程未动。

## 5. 验证报告写哪

| 内容 | 位置 |
|---|---|
| 本次启动/替换的**逐条命令与输出** | `D:\持久层能力架构\_scratch\` 下新开一个文件（例如 `install-report-<日期>.md`），格式照 `_scratch/smoke-report.md`：命令 + 输出 + 退出码 + 每层结论 |
| 三条验证各自的原始输出 | 同上文件内，一条一节，**贴原文**，不要只写「通过」 |
| 发现的缺陷 | `D:\持久层能力架构\dsh-graft-slice\docs\backlog\graft-slice-phase-a-issues.md`（A 系列=真缺陷 / B 系列=仪器盲区 / 第九节=保持未验证的项） |
| 若替换失败 | 同一份报告里的「回滚」一节，写清失败点（加载？注册？调用？）与当时的报错原文 |

**报告纪律**：命令 + 退出码 + 原始输出三者缺一不可；「跑过了」不等于「通过了」。

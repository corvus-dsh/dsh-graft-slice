# 替换真机旧版 —— 交接说明（给新会话执行）

> **这份说明不是给产出它的那个会话用的。** 产出它的会话正在被这个插件托管，替换它会动到那个会话自己的安全网。
> 执行者：**新开一个会话**，在新会话里按本文操作。
> 边界：**不 publish**（发布另有流程，且 beta 版本已在 registry 上冻结）；不碰另外三个仓。

## 二、替换之前必须做的一件事：停泊当前会话

**为什么**：这个插件承载着会话自己的水位与自动切片安全网（70% 提示模型自行收尾、75% 系统强切）。
替换它 = 换掉正在运行的这套机制。在生产路径上中途换件，最容易出的问题是
**旧实例仍在内存里跑、新版本在磁盘上**，于是行为既不是旧的也不是新的。

**怎么做**：在**新会话**里操作，让被替换的那个会话处于停泊/已结束状态，再执行安装。
不要在被替换的会话内部执行安装命令。

---

## 二、独立 profile 要求（不得使用 `desktop`）

**要求：整个替换与验证必须在「一个独立的 profile」里做，不得在 `desktop` 上做。**

这里的 `desktop` 指 `DSH_PROFILE_DIR` 当前指向的那个 profile（本机观测值
`C:\Users\89283\.dsh\profiles\desktop`）—— 它是用户日常在用的那个。

**为什么不能用它**：

1. **它托管的正是要停掉的那个会话**。这个插件承载会话自己的水位与自动切片安全网；
   在 `desktop` 上替换，等于一边被它托管、一边换掉它。
2. **失败会连带影响日常使用**。新版本若在加载阶段抛错（Service 注册、`cordis.patch.yml` 解析、
   `manifest.json` 字段），坏的是一整个 profile 的启动，不只是这一个插件。
3. **状态文件会被污染**。`.graft-targets.json` / `.retired.json` / `.transferred.json` /
   待点火队列都是**按 profile 的 data 目录**存放的；在 `desktop` 上试装会往真实台账里写东西。
4. **回滚粒度**：独立 profile 失败时直接删目录即可，`desktop` 毫发无伤；在 `desktop` 上失败，
   回滚要动的是用户正在用的环境。

**怎么做**：新建一个一次性 profile（名字自取，例如 `graft-smoke`），把它作为 `DSH_PROFILE_DIR`
再执行第三节的命令。验证通过后再决定是否替换 `desktop`；**验证不通过就直接删掉这个 profile**。

**三条禁令**：

- 不要把 `DSH_PROFILE_DIR` 指向 `desktop`（那正是本节要避免的事）；
- 不要手改 `desktop` 下的 `package.json` / `node_modules` 来「模拟安装」——绕过加载器的账，
  装完的状态无法回滚；
- 不要在验证未通过的情况下把新版本装进 `desktop`。

## 三、替换步骤

真机上当前是 `link:` 指向开发目录。规范路径是 CLI：

```powershell
dsh plugin list                              # 先看清现在装的是什么、来源是 link 还是 registry
dsh plugin remove dsh-graft-slice            # 摘掉旧的
dsh plugin add "<上面的 tarball 绝对路径>"    # 装新的
dsh plugin list                              # 确认版本与来源都变了
```

**已知阻塞（上一轮实测，未解决）**：`dsh` **不在 PATH**（`where dsh` → exit 1）。
若你那边同样如此，请**先解决 CLI 可用性**再按上面执行；
**不要**去手改 profile 目录来模拟安装 —— 那绕过了加载器的账，装完的状态无法回滚。
（这条已登记在 `docs/backlog/graft-slice-phase-a-issues.md`。）

## 四、装完必须验的三件事

| # | 验证 | 期望 | 为什么是它 |
|---|---|---|---|
| 1 | `plugin_manager` 的 `list_bundles` | 版本 = `0.9.2-beta.1`，来源 = 那个 tarball（不再是 `link:`） | 证明**装的是新件**，而不是旧的 link 还在生效 |
| 2 | `graft_debug_status` | 能正常返回水位/锁/待裁定状态 | 证明插件**加载起来了**、Service 注册成功 |
| 3 | 一次**真实**切片（`graft_slice_and_inject`，目标会话自己指定） | 返回 `ok`；目标会话可冷启动；看板有锚点行 | 证明**跑得对** —— 前两条只证明"在"，这条证明"能用" |

补充（可选，成本很低）：让它对一份真实日志跑一次 `buildTape`，确认锚点行文案是三种之一
（`第 N 代会话` / `一个原始会话` / `一个代次未记录的会话`）—— 这是本轮改过的地方。

## 五、出问题怎么回滚

**回滚 = 把旧的装回来**，不是改代码。

1. `dsh plugin list` 找到旧版的来源（此前是 `link:D:\持久层能力架构\dsh-graft-slice`）。
2. 若是 `link:`：把开发目录 `git checkout` 回替换前的提交，再 `dsh plugin add <那个目录>`，
   加载器会重新按 link 解析 —— 因为 link 指向的就是源目录。
   **替换前的提交号请在你替换前先记下来**（`git -C D:\持久层能力架构\dsh-graft-slice rev-parse HEAD`）。
3. 若是 registry 版本（如 `0.9.0-beta.2`）：`dsh plugin add @corvus-dsh/dsh-graft-slice@0.9.0-beta.2`。
4. 回滚后重复第四节的三条验证，确认回到可用状态。

**注意**：会话状态文件（`.graft-targets.json` / `.retired.json` / `pending-ignitions`）**不在这个包里**，
替换插件不重置它们。若切片中途失败留下的待裁定状态，用 `graft_debug_status` 看，不要手删。
